# Foundation policy changes

The approved A–D implementation replaces the following mechanisms. This records semantic changes to the gates; content hashes establish identity, not human approval.

| Previous mechanism | Disposition and retained protection |
| --- | --- |
| S3 2048-byte instruction cap | Removed. Root-only instructions and exact CLAUDE pointer remain paired checks. |
| S4 plans, common path words, JSON keys | Removed. Generated roots, raw archive/world/log extensions, authored size limits and schema/digest-declared binary assets remain. Ordinary source packages, plan documents and profiler schemas have positive regressions. |
| S5 exactly seven findings | Removed. Every row still needs an evidence scope and frozen evidence identity; new findings may be added. |
| S6 text matching GPU locks | Removed with its filename/word specimens. The runtime's nonblocking exclusion is tested behaviorally; no scheduler or lease service is introduced. |
| D10 correction text pointing to its own rule | Removed with circular specimens. Corrections require reproducing the failure and preserving a negative/control regression. |
| D2 filename discovery and engine string matching | Removed; packaged ServiceLoader registration and bytecode provider isolation replace unused generated names. |
| D4 class-name text reachability | Removed. Packaged extension registration and actual compiled dependency boundaries are the source-port owners of these guarantees. |
| D3 universal publisher | Narrowed to effect-owner modules and test fixtures; an unrelated library's raw result writes still fail. In-memory StringIO/BytesIO writes are permitted. |
| D7 CODEOWNERS/remote routing | Removed. Local-only scoped authorization and explicit policy diffs replace unconfigured remote protection claims. Exact exception tokens, sites and rationale remain checked. |
| Exact test-name equality | Required test names are a minimum subset. Ordinary discovery may grow; failure, skip and zero-test results still refuse. |
| Shebang expiry | Structural shebang exceptions are permanent, with exact token/site validation. Arbitrary comment exceptions remain forbidden. |
| Self-test totals | Bytecode/tool summary rows reference the assertions actually executed elsewhere; they are not counted as independent tests. |

`./check --fast` runs the ordinary compile, formatting, typing, policy and CPU tests and labels the outcome partial. `./check` also validates paired specimens and tool wiring. Tool self-tests declare relevant inputs and their output to Gradle, enabling visible reuse; `./check --fresh` forces execution. `build/reports/foundation/gradle-tasks.json` records actual Gradle task outcomes, including reuse and not-run steps. A failure never becomes full qualification because an older step report remains on disk.

The private evaluator for the fresh-agent exercise must independently verify the requested behavior and unchanged safeguards. This document is not an evaluation score or a claim of live runtime correctness.

Pinned native Mixin entry-point directives are structural, exact-site exceptions tied to required bytecode selectors; they do not expire by calendar date. Unused-method/parameter checks remain active elsewhere. Runtime native writers buffer their actual serialization and announce bytes/deletions to the journal before mutation.

Provider bytecode is restricted to domain/engine contracts, standard Java and its own provider module; integration/storage shortcuts and cross-module coupling have negative/control specimens. The fresh-agent repair also closes numeric overflow through direct and decoded measurement admission. Scope reporting is derived from actual task rows, preserving full/partial labels after Gradle callbacks. Runtime child publication uses the existing storage owner; no worker write exception was added.
