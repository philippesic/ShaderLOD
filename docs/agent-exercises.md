# Lightweight agent development evaluation

Three claims stay separate: deterministic correctness, an agent's ability to complete a task, and causal improvement in agent productivity. The current evidence supports one scoped unaided repair and a deterministic extension round trip. It establishes no general productivity gain.

The [trial record](evidence/agent-exercise.json) preserves snapshot, public task, model/harness, budget, no-hint outcome, cache scope, independent assessment and evidence locator. A fresh-context agent worked in an isolated Git clone at the committed checkpoint. It repaired a genuine finite-number admission defect, added regression tests and passed the full CPU gate without editing policy/locks or launching a GPU. The frozen assessor lived outside its declared workspace; this was procedural isolation on a shared full-access host, not a security sandbox. The agent received the behavior requirement, not the private numeric variants.

The independent assessor rejected the plausible-wrong baseline (13/19), accepted an independently bounded reference (19/19), and accepted the submitted repair (19/19). This calibrates these numeric cases, not every possible defect. The agent correctly disclosed a check-scope reporting error, fixed separately by the parent. Exact terminal/tool/provider waiting and complete call counts were not instrumented, so no end-to-end completion-cost claim is made. The first shared-tree read-only trial was invalidated by concurrent source changes and remains excluded rather than recast as success.

The parent separately planted a module in a disposable clone, packaged the JAR and used an external JVM reader to prove real registry activation and unsupported-input refusal. Removing only that module directory and rebuilding left neither registration nor class orphans. A fixture annotation compile error was retained and corrected without changing gates. This is deterministic API proof, not a second independent agent trial or live optimization qualification. [Frozen assessor/fixture source](evidence/assessment-source.json) is retained as inert data; production never loads it.

Use these small task families only when their capability exists: routine source/test change; diagnosis with an already-correct no-change control; module add/remove; restoration/interruption; and truthful mixed-evidence reporting. The latter families have deterministic CPU coverage, but no fresh-agent success is claimed for unrun families. Provide public behavior requirements and retain independent held-out acceptance. Pin snapshot, assessor, tools, instructions and budget before evaluation; preserve failed, blocked and assisted outcomes. After a frozen unaided failure, a small recorded hint ladder can diagnose discoverability versus API/check versus reasoning gaps; it never relabels initial failure.

Critical unsafe actions or false qualification block the affected workflow regardless of speed. Correct refusal can succeed when authority/capability is absent. Model judgments alone cannot establish correctness or safety: reconcile structured facts against receipts, then adjudicate ambiguous explanations. A compliant result with avoidable rescue is assisted. Unknown causes remain unknown.

For an expensive repository-design decision, predeclare the practical improvement that would justify it and a bounded matched comparison on equivalent capabilities with fresh variants, balanced order, model/harness/resources/cache controls and all attempts retained. Change one mechanism to attribute its effect, otherwise report bundle-level evidence. Rerun a repaired failure class plus a routine regression when that can change the decision; do not build a permanent evaluation platform or tune against every assessment case. No scientific benchmark workloads, thresholds or statistical method are chosen here.
