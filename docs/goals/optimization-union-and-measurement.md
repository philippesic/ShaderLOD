# Optimization union, independent switches and measurement

Active goal authorized by Philip on October13,2026 Pacific. Replaces the prior
execution objective; prior work and unfinished evidence remain linked in
[cross-shader integration](cross-shader-performance-integration.md).

## Outcome

Collect the union of currently implemented shader and CPU/rendering optimizations.
Port every applicable item to Photon, Complementary Reimagined, Complementary
Unbound, BSL, MakeUp UltraFast, Sildur’s Vibrant, Solas, Bliss and AstraLex, with
one owning agent per shader. Schedule owners within available native capacity.
Deliver independent optimization switches and usable frame/CPU/GPU/FPS measurement
tools for changing one optimization while holding all other settings/work fixed.
No combinatorial search or automatic winner selection; manual validation with
Philip follows delivery. New measurement/toggle infrastructure is authorized.

Both loaders and all five supported Minecraft versions remain scope (90 cells),
Iris required, DH/PBR compatibility. Native quality/AA and original/Off/Quality/
Cancel/failed-Apply/mismatch recovery remain required. Preserve exact upstream
ancestry, licenses, existing closed/fixed trials and historical allocations.

## Acceptance

- Complete source-backed optimization inventory, including current optional and
  experimental implementations; identify diagnostics and closed historical trials
  separately rather than silently counting or omitting them.
- Per shader, every inventory item has an implemented consumer and independent
  switch or a reviewed concrete absent-feature/math/API reason it cannot apply.
  A hardware blocker is unverified runtime evidence, not proof a port is absent.
- All applicable ports delivered through actual selected graphs and normal builds.
  Native integration/normalization/AA/material effects and recovery stay faithful.
- Switches actually isolate the named work. Broad presets or global On/Off alone
  do not satisfy independent optimization control.
- Actual frame wall time, render/process CPU timing and GPU timing with declared
  scope, units, resolution, availability, validity and provenance. GPU timing must
  come from a real GPU source; unsupported hardware is explicit, never fake data.
- Repeatable single-toggle paired measurements with settings/source/hardware/scene
  pins, warmup, reload handling, raw samples, summary/delta and baseline drift.
  Instrumentation correctness is demonstrated; profitability is a later user phase.
- Practical user instructions and usable previews. Full port/toggle/measurement
  scope is the finish line, not an early passing shader or helper.

## Ownership and first operation

Parent owns complete inventory, shared contract, scheduling/integration/Git and
acceptance. One shared infrastructure owner handles independent configuration,
uniform delivery and frame/CPU/GPU measurement. Nine separate shader owners
port their own recipes/helpers and return isolated changes for shared-loader
joins. No worker recursively delegates or takes a client/build/GPU lane.

Fresh census at goal start found no Minecraft/dev-client/Gradle jobs; prior
workers are terminal/interrupted. No runtime is launched by this goal-start
record. Parent schedules exact resource ownership before real probes.

First milestone: finish the union inventory and switch contract, then obtain
concrete per-shader port patches and a working timing/toggle slice. Existing
artifacts, source proofs, genuine installed producers and restoration receipts
are reused for unchanged dependencies.
