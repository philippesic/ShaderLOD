# Agent operations

## Choose and bound the operation

[STATUS](STATUS.md) alone owns current scope, authorization, allocation and last
observed state. Use `python3 scripts/project_checkpoint.py show docs/STATUS.md`;
read linked goal sections relevant to the task. Maintenance does not resume a
paused or unobserved runtime campaign.

For an existing-concept port, name the working implementation, missing joins and
actual selected public consumer. Prepare the changed consumer and authentic
caller inputs together, then bind the integrated artifact. For an optimization,
identify active native work and take an early matched original/control/enabled/
return cost and quality observation. An inactive effect is coverage, not a gain.
Use [EVALUATION](EVALUATION.md) for the claim; a manual preview or control increment
does not require every historical performance protocol first.

Put the relevant assignment details in the worker message or existing attempt;
no new form or launch gate is required:

- **Outcome:** family/version/loader/dimension, preset, selected consumer and next
  user-visible result; for work reduction, native → selected active work.
- **Reuse:** working implementation, pinned inputs and valid unchanged evidence.
- **Ownership:** exact files/worktree, dependencies, exclusive resource owner,
  allowed actions and report destination.
- **Acceptance:** authentic input and real entry point, checks and evidence limits.
- **Budget and handback:** review/stopping boundary covering setup, workers,
  repairs and handoffs; changes, actual checks, evidence and exact owned processes.

Rank hypotheses by active removable work, likely total benefit, uncertainty,
effort and visual risk. Batch cheap independent defects with saved inputs and
[preflight](EXPERIMENT_PREFLIGHT.md); stop diagnostic work when the actual consumer
answers the question. The parent targets the next useful result and explains the
main delay across preparation, rendering and evaluation. Repeated same-cause
failure or an overrun of the roughly 15-minute auxiliary review budget calls for
a simplify/justify-extension/switch decision. If uncertainty remains, use one
bounded independent proceed/change/park review, with no execution or allocation
authority; do not add a standing supervisor. Preserve healthy allocated work and
closed negative trials.

## Assignments and integration

Partition by remaining dependencies, not automatically one worker per shader.
Shared API/resource repairs have one owner and one integration. Keep authentic
caller preparation with consumer ownership through handback; do not accumulate
patches awaiting unassigned caller work. Parent accepts actual artifacts/checks,
with independent review for consequential correctness or speed claims.

Repository role briefs under `.codex/agents/` describe domain responsibilities;
use [the runtime adapter](T3_AGENT_RUNTIME.md) for actual availability, dispatch,
review rounds, worktree setup and cancellation. A child handback does not finish
the parent outcome or transfer a client lane.

## Client, build and GPU ownership

Before launch, reconcile actual availability with the last observation. Record
hardware, component pins, scene, command, session, PID/birth/argv, finite deadline
and exact stop procedure. Use existing `scripts/dev_client.py` supervision and
exact-client stop APIs where supported; never kill by broad process name.
Remote hosts and allowed actions come from current STATUS authority.

Quiet measurements exclude source edits, builds, tests, encoders and unrelated
CPU work unless the protocol permits them. An untimed control operation can
release independent source preparation when its owner permits it. Do not change
a live freeze or reinterpret its quiet contract. Verify exact termination and
save/lock release before reporting the lane free. Analysis follows the operation's
executable restore/verify/release path without consuming its recovery allowance.

Build success, startup, in-world rendering, DH terrain, active feature consumption,
quality and speed remain separate evidence. Record hardware/OS; one platform does
not qualify another. Use [benchmark storage](BENCHMARK_STORAGE.md) for capacity/
retention and the [finite speed caller](RENDERER_BRACKET_CONSUMER.md) for supported
tuples. Adoption uses the actual normal producer, compiled resource and caller,
with the current receipt rather than an old staged patch. Keep final freeze/
preflight/deadline stamping/launch in one local operation once callers are ready.
Version-specific builds use their documented executables.

For maintained non-Photon adapters, use the builder's `--sync-resources` preview
and explicit `--apply`; do not hand-copy recipes into ten builds. See
[verified commands and limits](DEVELOPMENT_THROUGHPUT_REVIEW_20261012.md).

## Checkpoints, reports and handoff

Update managed STATUS at meaningful milestones with actual evidence, next action,
owners/jobs and unchanged allocation/authorization. Use
`python3 scripts/project_checkpoint.py` show/lint/update with the observed prior
SHA; inspect `--help` for update arguments. Preserve the typed schema and exact
history; do not append a competing current block or refresh time as progress.
Record an outcome once and link its evidence; active lesson summaries link the
preserved historical episodes.

Before handoff record exact owned jobs, stop path and next executable action.
After resume verify actual workers/jobs/artifacts before acting. Keep one stdout
reader per operation. Distinguish an attempt closing from Full completion using
actual terminal metadata. For elapsed-time reports distinguish preparation,
active render/evaluation time and waiting, and name the main delay; do not present
process health as a measured result. Runtime continuation semantics live in
[the adapter](T3_AGENT_RUNTIME.md).
