# Bounded functional verification

Philip specified the Asahi MacBook Air. No RTX 5080 workload was launched. Runtime verification is separate from benchmarks and never produces a performance verdict. The required first target remains pinned Complementary Reimagined r5.9.3 with DH, original options, native 2560×1600 and native AA. Failure of that target is a held gate; an absent-DH diagnostic cannot substitute for it.

Setup uses verified pins in `dependencies/runtime.lock.json` and `dependencies/primary-pack.json`. Bootstrap stages exact archives, Java and ARM native libraries. Main and development code compile against the pinned Iris, Sodium, DH, NeoForge and Minecraft versions. The shipping JAR excludes development providers, probes and profilers.

The maintained entry prepares the pinned JDK/Python, verified runtime artifacts, main JAR/package audit and development probe before starting bounded execution:

```
./verify --runtime --profile run-client-absent-dh --without-dh --display /run/user/1000/shaderlod-display/environment.json --receipt build/reports/live/unique-attempt.json --ownership-root /run/user/1000/shaderlod-ownership --timeout 180
```

This example is the explicitly separate no-DH diagnostic. The required target omits `--without-dh` and uses its DH-enabled task-owned profile. Use only an actually allocated display/host window; the example does not grant authority. Prepare the world via `shaderlod_host.storage.copytree`, never mutate a shared source world. All profile/display/output/ownership/timeout arguments are required; a bare `./verify --runtime` refuses. Existing completed probe outputs refuse overwrite and must be preserved first. No mode changes shader quality.

The bootstrap builds `writeFunctionalLaunch -PfunctionalProbe` and `packageAudit`, then reads the build-owned shipping-JAR path and exact Java argument vector from `build/moddev/functional-launch.json`. The maintained lower-level Linux executor remains `python3 -m shaderlod_host.runtime_live --help`. `--shipping-jar` removes loose main class/resource registration while retaining the separate test probe. `--native-control` excludes ShaderLOD and its development mod and is a separate negative reference; it has no functional probe success receipt. The entry's switches select behavior, not execution authority.

The Linux watchdog bounds the Java process group even if its submitting agent disappears. The nonblocking host/device advisory lock excludes cooperating users only; inspect ambient occupancy before launch. Runtime executable inputs are hashed before and after the attempt; drift invalidates it. This covers declared JVM inputs, compiled resources and discovered JARs, not an exhaustive attestation of system-loaded libraries. Native Windows execution and cross-host artifact transfer remain unavailable.

The v3 development probe drives actual SettingsScreen widgets through unapplied Cancel, native Apply with unchanged TAA, Off, identity-provider Apply, Cancel while active, and deliberately invalid shader compilation followed by restoration. LINKED is distinct from ACTIVE: a required Iris final-level-render callback must return for the same pipeline before a later tick confirms the generation and submitted-frame witness. This demonstrates submission through the selected graph, not GPU completion or visual equivalence. Independent host validation joins archive hashes, increasing generations, options, source, native dimensions, output hashes and restoration observations. A producer PASS field alone fails validation. Raw PNGs are evidence of output, not an image-quality oracle.

Schema v1 receipts retain their original limited linkage-only meaning. The initial v2 exercise added frame/UI witnesses; visual inspection then exposed transient empty terrain after reload. The v3 probe additionally waits for a nonempty rendered-section observation and records it for baseline and identity output. Its reader refuses older schemas rather than inventing observations. Original attempts remain immutable; later corrected cohorts link to them. No receipt schema or editable authority field establishes human authorization.

The opt-in development mod exports bounded CPU frame intervals and asynchronous GPU timestamps with generation/frame ownership, pending, lost and invalid health. `/shaderlod-profile` writes a diagnostic export. Collection never waits for a pending query; context changes preserve unavailable/loss distinctions. Per-pass cost maps, calibrated instrumentation overhead, statistical comparison and optimization selection await the benchmark stage.

The CPU host command exposes `plan/run/verify/report/doctor/recover`, with an optional owner-bound control file and explicit disk reserve. A killed submitting runner leaves its charged attempt and exact child identity. Recovery only marks it interrupted after the recorded host/boot and process-group lifetime are provably quiescent; it never kills a possibly foreign process, frees a spent budget or rewrites an old result. Missing/corrupt ownership, another host/boot and a live group refuse. A new permitted attempt retains prior cost. A watchdog killed before publishing its child identity requires adjudication; absence of metadata is never treated as proof of cleanup.
