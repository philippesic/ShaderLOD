## Secondary low-risk arithmetic candidate: Complementary prior-weight reuse

Both Reimagined/Unbound r5.9.3 pin the same volume member `d380c3243df73b390433c015fcb5b9182cf98a511b49f7a98d5ccac1313ae8ff`. Their loop computes `currentWeight=F(lastDistance)` and `nextWeight=F(nextDistance)`, where `F(x)=smoothstep1(pow(x/maxDistance,fogCurve))`, then accumulates their difference and assigns `lastDistance=nextDistance`. Neither denominator nor exponent changes inside the loop. Thus the next iteration recomputes exactly the prior nextWeight. A carried scalar initialized with native `F(0)` and updated alongside lastDistance eliminates that repeated expression without changing sample counts, locations, texture operations, shadow eligibility, additive recurrence, native AA or dither.

All loop exits before accumulation terminate the loop; there is no continue. The entity-depth break occurs before both accumulation and tail assignment. These exits therefore do not require another cache-update path. Retain the original initial expression rather than simplifying to zero without a domain proof. For k completed intervals, native weight evaluation count2k becomes k+1 (k−1 fewer pow/smoothstep evaluations); final incomplete iterations and compiler optimization alter actual cost. Default near count10 increases up to15 with scene intensity; already-selected Balanced near count9–14 remains unchanged. Overworld far count is only1 and should not be budgeted further.

This is an explicit pack-specific compiler optimization opportunity, not a promised speedup: the native compiler may already perform loop-carried reuse, register pressure may offset savings, and there is no measured shader/pass fraction. A private candidate should preserve original graph recovery and use the existing generated Balanced route, with runtime enable fallback made explicit before main adoption. A CPU equivalence model can prove its algebra under modeled arithmetic, not GLSL driver bit identity. Parent has the exact scope proposal; no maintained sources were changed in this analysis.

## Why the obvious BSL/Bliss copies are less useful

BSL10.1.8 default AO_METHOD0 performs four angular groups, each with two depth fetches, plus four normal-reconstruction depth fetches. The existing ceil(.875N) policy maps4→4 Balanced: a group-preserving copy of Astra AO saves nothing. Performance maps4→3 but normally selects BSL's native renderer graph, bypassing the adapter. Shrinking individual paired samples, changing normalization/rotation or changing policy would be a new quality choice. The native AO pointiness correction also shares group normalization; a denominator-only copy would be incomplete.

BSL's seven logarithmic light-shaft positions use `exp2(i+dither)-.95`, sum shadow/blocklight and divide by7. Balanced maps7→7; merely changing the upper loop bound truncates distant support. Proper reduction would resample the exponent domain and preserve sum normalization as well as currentDist-dependent blocklight weighting. This has no useful Balanced reduction under current policy and should not consume a port attempt.

BSL default volumetric clouds retain per-step `cloud=mix(cloud,1,noise)`, cloudLighting weight `noise*(1-cloud²)`, multiplicative distanceFade, separate cloudFaded and cloudViewLength first-crossing feedback. Reducing samples and widening step alone changes all these. Even constant-density transmittance requires alpha'=1−(1−alpha)^(oldN/newN); that correction alone does not preserve lighting, distance fade or first-hit feedback. The optional Aurora24→21 transfer is mathematically simpler but AURORA0 defaults mean no default work saving. Existing closed reflected-cloud classification, saturation, early-alpha and renderer no-gain trials remain closed.

Bliss already budgets default VL_SAMPLES in its actual fog consumer before its exponential sampling distribution and differential dd. Native fog/atmosphere/cloud contributions track absorption separately. The active source repeats the identical pow(expFactor,(i+dither.x)/SAMPLECOUNT) expression in d and dd and repeats several extinction exponentials in color/transmittance pairs. Naming each once is straightforward exact-expression reuse, but local common-subexpression elimination is standard compiler territory and cannot be represented as a new GPU saving. A more aggressive recurrence would change floating-point evaluation/accumulation and requires its own error bounds; it is not a necessary concept port. Native cloud march/inner sunlight loops also carry their own physical stride/extinction and temporal reconstruction, so global count substitution is insufficient.

## Prioritization and speed claims

Prefer the explicit MakeUp End consumer for direct coverage, and keep Complementary weight reuse as a bounded arithmetic hypothesis if the parent wants an additional candidate. Do not spend another attempt on count-only BSL AO/shafts or optional default-off Aurora. The shared policy, selection/recovery service and shared build resources are already reusable; remaining productive work is the short pack-specific consumer equation and authentic dimension/pass proof.

Older MakeUp/Sildur renderer wins reduced CPU/driver submission overhead using cached fills/coalescing on older version paths. They did not establish that fog, cloud or AO shaders dominate frame time, and their percentages do not transfer to sample budgets or newer copied-submission routes. For an effect occupying unknown frame fraction f, reducing its relevant work by fraction r has idealized total cost saving at most f×r before overhead and other bottlenecks; neither f nor proportional scaling is established here. The right immediate deliverable is a truthful runnable candidate and fresh observation, not a large inherited percentage.
