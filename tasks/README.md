# Tasks

This directory describes unfinished multi-session work. One task file owns one active goal; use a descriptive filename. This README defines the convention and is not an active task.

Each task has a title and exactly these sections, in order:

- `## Goal`: the intended outcome.
- `## Authorized`: approved scope, limits and decisions still needed.
- `## Done when`: observable completion criteria.
- `## State`: current facts and blockers; rewrite instead of appending a diary.
- `## Next`: the next useful action and its owner when relevant.

An open task is context, not automatic authorization to resume it. Follow the user's current request. Routine single-session fixes need no task file.

Lifecycle: open task → investigate → write a result if warranted → update current docs → prune obsolete code within scope → update FINDINGS → close task. Delete a completed task; Git preserves its history. Do not retain completed tasks as reports or implementation histories. An unresolved scientific result can close a bounded investigation; retain a task only when further work is assigned.

Use [close-results](../skills/close-results/SKILL.md) with [the project result specification](../docs/results.md) for meaningful investigation closeout. Routine fixes update source, tests and current documentation without automatically creating a result page.
