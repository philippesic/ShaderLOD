# ShaderLOD working rules

Read [STATUS](docs/STATUS.md) and its latest active-goal checkpoint before
substantial work. Historical assignments are evidence, not current work. Use
[EVALUATION](docs/EVALUATION.md) for evidence and
[AGENT_OPERATIONS](docs/AGENT_OPERATIONS.md) for execution and handoffs.

Current human priority is direct shader-family support: extend existing mechanisms
and control/recovery paths across the declared shaders before pursuing unrelated
new optimizations. Use [the support frontier](docs/SUPPORT_NEXT_20261011.md) and
current STATUS to choose a concrete missing family/tuple. Keep native-original
hardware blockers explicit and move to another runnable family rather than grow
an unbounded driver or benchmark framework. This preserves the full 90-cell scope.
For existing-concept ports, use the compact assignment in AGENT_OPERATIONS:
name the working implementation, missing joins, actual selected consumer and
claim-specific acceptance. Reuse evidence for unchanged dependencies.

- Continue the authorized unfinished outcome: useful original-relative rendering
  gains and actual mod-controlled shader LOD across Photon, Complementary
  Reimagined/Unbound, BSL, MakeUp UltraFast, Sildur’s Vibrant, Solas, Bliss and
  AstraLex. Follow the current human scope in STATUS for active shader families,
  versions and loaders; practical renderer gains and shader-work reduction remain
  distinct evidence. A previously deferred port is active again when the human
  restores it to scope.
- Both NeoForge and Fabric across MC 1.21.1, 1.21.11, 26.1.2, 26.2 and 26.3
  are intended scope. Iris is required; DH is optional for users but required
  compatibility evidence, as is PBR. One working version does not prove others.
  Use explicit pinned adapters; no universal GLSL rewriting or inferred support.
- Plan the selected candidate through preparation, real driver consumption,
  quality, early matched original/control/enabled/original-return cost, and
  restoration. Implement the smallest complete useful slice. Batch independent
  cheap defects using actual launcher records before expensive work.
- Rank hypotheses by active expensive work, plausible total benefit, uncertainty,
  preparation cost and visual risk. Charge setup, repairs, workers and handoffs
  to the same attempt. After two failures with one cause, diagnose or change
  strategy. The roughly 15-minute auxiliary budget is a review trigger, not
  permission to weaken gates or stop healthy work. Reuse existing tools.
- A failed candidate closes that experiment. Continue the authorized project on
  a distinct justified premise; do not rescue closed fixed trials by tuning
  scene, preset, threshold or filter. An explicit user stop takes precedence.
- Delegate independent bounded deliverables when permitted, usually up to four
  useful workers. Parent schedules and integrates; workers never recursively
  expand the team. Assign files, dependencies, acceptance, resource owner,
  budget, stopping boundary and report destination. Use file partitions or
  isolated worktrees; preserve other edits. Verify terminal workers actually
  restart with the supported new-turn tool.
- One acknowledged owner controls the client/GPU/build lane. Quiet measurements
  exclude unrelated CPU work unless the protocol allows it. Preserve healthy
  jobs. Record exact process birth/argv, session, deadline and stop procedure;
  never stop by broad process name. Written checkpoints do not transfer control.
- Distinguish source/build, actual rendering, loaded options, consuming shader
  paths, avoided work, still/motion quality, speed and compatibility. Keep native
  AA/quality and faithful Off/Quality/Cancel/failed-Apply/mismatch restoration.
  Preserve failed evidence; no fabricated passes or weakened fingerprint guards.
- Keep one active project goal in STATUS and docs/goals. Only explicit user
  requests create native Goals or user-owned chats. No push, publication,
  Windows SSH, Vulkan or external messages beyond current authorization.
- Keep worlds, downloaded sources/jars, builds, captures and raw logs out of Git.
  Preserve source ancestry, versions/hashes, licenses and unrelated dirty work.
  Commit coherent scoped changes with short subjects and no body/coauthors.
- Update the current checkpoint at milestones; retain linked history. Returning
  users need objective/baseline, change, meaning, observed current state and next
  decisive step, not hashes and stage codes. Give meaningful updates about once
  a minute during interactive work; answer steering promptly and resume.
- Record demonstrated coordination failures in docs/USER_LESSONS.md factually,
  including the agent’s contribution and practical correction. Do not label
  disagreement a confirmed user mistake. Major product/research choices belong
  to the user; record options in docs/DECISIONS.md and continue independent work.
