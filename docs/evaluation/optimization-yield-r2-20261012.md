## Finding

The small visible gain is not adequately explained by “shaders differ.” Several current consumers are provably zero-reduction at the selected native count/preset, some features are off, and eligible Performance intentionally selects a different mechanism. These are cheap source/option facts that should have been joined before expensive gain-oriented work. Compatibility and recovery ports remain real useful deliveries, but their completion does not increase the amount of expensive work removed.

The first audit's resource propagation and final-runner fixes remove genuine repetitive work. They do not by themselves improve this optimization yield. The larger correction is to select a named active consumer with nonzero arithmetic opportunity, then establish its actual cost early. Current MakeUp clouds and Complementary near-volume ports are better premises than their older narrow reflection budgets. They are still approximate sampling reductions with unmeasured total-frame benefit and quality.

### Stronger no-op finding: MakeUp reflection budget uses the wrong denominator for opportunity

Current manifest budgets post-crossing refinements from **RAYMARCH_STEPS**, not from actual remaining refinements. Native `config.glsl` sets10. `water.glsl` starts `searchFlag=false`, iterates i=0..9, and sets searchFlag only after the current iteration's sampling. Therefore at least one iteration is coarse, leaving at most9 refinements. Balanced's minimum possible limit is ceil(10*.875)=9: it cannot stop any work, even in the far band. Near/intermediate limits only increase it. Generated Performance's minimum limit8 can save at most one iteration, and only if the first coarse iteration already finds the crossing; a crossing on iteration1 or later leaves≤8 refinements and saves none. The native loop can still run10 total iterations in those cases.

This is a static conclusion at native10, independent of unknown scene coverage. It does not imply lowering the guard/minimum is safe, nor authorize a new reflection algorithm or a retry of the closed trial. The newer cloud10→9/8 join is a distinct, more direct work opportunity.

### Several earlier Balanced “optimization” paths could not remove native work

At native counts, BSL reflection4/6, Sildur volume6 and MakeUp total-loop10/post-crossing limit9 all save zero under Balanced. Solas reflection6 and Astra reflection6/AO six groups also save zero. Reimagined/Unbound can reduce their10-refinement branch to9 but not their6 branch, and only beyond sufficient distance/valid crossings. New volume ports improve this picture for MakeUp and R/U; BSL optional Aurora does not improve its default-active workload.

These are integer quantization facts. A 12.5% policy label is not a 12.5% loop reduction, much less a frame reduction. The uniform helper is also uniform quality budgeting, not distance LOD; only the reflection helper consumes near/far/transition.

## Additional parent-identified production cost, independently verified

Current NeoForge26.2 [MakeUpBindingCompatibility](../../ports/26.2/neoforge/src/main/java/com/pp/shaderlod/integration/bindingcompat/MakeUpBindingCompatibility.java) runs `sourceStamp(...)` from render-thread `enter()` whenever the50ms bucket changes. `PROBE` guards the counter increment only, not hashing. All three family `*SourceCertificate.stamp` methods use `sha(Files.readAllBytes(selected))`, additionally original archive bytes for generated selection, plus generated marker/state reads. Their comment says “explicit untimed mode”; the caller does not impose such a mode. This source fact is independently verified and is distinct from the historical dev speed path.

The actual BSL MAIN report `dev/logs/concept-transfer-r1/bsl-neoforge-main/runtime-r1/runtime-report.json` records cumulative sourceStampReads603/1215/1826/2437 at original/On/Quality/Off:612/611/611 additional stamps across successive stages. These establish actual invocation, not measured cost. At the parent's independently recorded native/generated archive sizes1,134,153/1,134,776bytes, a steady20Hz model means22,683,060 native archive bytes/s or45,378,580 generated-plus-original bytes/s passed through full-size byte arrays, before marker/state/ZIP overhead. These are logical read/allocation volumes, not measured physical disk traffic or FPS impact;20Hz is the bucket cadence model, not a strict per-second cap after lifecycle resets.

This is a concrete direct development opportunity without changing shader quality: stream the same complete SHA-256 input through bounded buffers, preserving all-byte tamper detection, exact digest and same cadence. It removes archive-sized temporary arrays but does not remove hashing/reads and cannot promise a speedup. A lifecycle-only hash policy would change the detection contract and needs separate explicit proof; do not replace hashes with size/mtime or weaken invalidation. Parent may assign a bounded implementation/review. This worker has changed no source. The normal shader runtime remains paused, so future runtime cost is unmeasured.

## What can be bounded honestly

Let s be the baseline frame-time fraction spent in the particular eligible loop, q its effective removed fraction after count floors/coverage/breaks, and h the added cost as a fraction of baseline time. A simple serial-cost model predicts Tnew/Told≈1−s*q+h. It assumes cost proportional to removed iterations and no occupancy/cache/CPU-GPU bottleneck changes; it is not a measured GPU model.

For MakeUp cloud10→9, q at most0.10 for nominal cloud iterations. With zero overhead and unrealistically s=1, FPS ceiling is1/0.9−1=11.11%; if clouds were10% of baseline cost (illustration only), predicted total saving is1%, about1.01% FPS. For cloud10→8, corresponding all-cost ideal ceiling is25% FPS. Neither s nor effective q has been measured. Native intervals and integration formulas retained do not establish equal quality.

For Sildur B6→6, BSL native water4→4/Aurora-off, and MakeUp native reflection Balanced, q=0 for the specified operation. Extra controls/branches can add work without removing it. For Astra P AO24→20 reads, the nominal read reduction is4/24=16.67%, not16.67% frame speed; no Mac execution exists.

The0.04042037% renderer command fraction is **not** a frame-speed upper bound: command costs differ and batching may alter CPU overhead. It is strong evidence of a small structural opportunity and motivates stopping that fixed premise. The old spatial design's +20N attachment bytes at4,975,872pixels (94.907MiB/frame nominal extra writes), duplicated classification and full fallback overhead were also source-computable before broad integration; these are nominal traffic, not measured DRAM throughput. [Spatial cost audit](../SPATIAL_COST_AUDIT.md) and closed rejection preserve that lesson without reopening it.
